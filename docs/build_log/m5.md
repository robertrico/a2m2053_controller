# M5: writing and formatting on the board

Date: 2026-10-11. Plan: `docs/superpowers/plans/2026-10-11-m5-write-format.md`, Task 10.
Spec: `docs/superpowers/specs/2026-10-11-m5-write-format-design.md`.
Firmware: branch `m5-write-format`, first flashed at `e4cb5cf`, then `61d4690`
(READY fix, below). Drive A in the bracket. Scratch disks: disk 1 ("TEST write",
formatted /WRITE on the IIe + working UniDisk) and disk 2. REF800K never in the
drive; its image was only read on the Mac.

**Result: PASS.**
- Sector write + verify: block 100 rewritten; a full re-read differs from the
  pre-write snapshot in block 100 only, which reads 512 x `A5`.
- A disk formatted and written by our board (disk 2) catalogs in the working
  UniDisk on the IIe: ProDOS lists `S5,D1:/REF800K` with DATA0-DATA5 and README.
  ADTPro image of disk 2 read through the working UniDisk (`TESTWRITE2.po`):
  0 blocks differ from REF800K, SHA-256 identical (`bfed064f...`).

Console log of the whole session (every command and reply, with notes):
`docs/captures/m5/2026-10-11_console.log`.

## What we measured

Scope: CH1 /WRTGATE (CN104 pin 10), CH2 WRTDATA (pin 18), CH3 RD (pin 16), 10x
probes, ground on pin 1, 250-500 MSa/s. Captures in `docs/captures/m5/`.

| Measure | Value | Spec (ERS86) | Capture |
|---|---|---|---|
| Gate low, one data field (716 bytes) | 11.70 ms | 716 x 16.34 us | `_write_whole_1ms.png` |
| T3: gate low to first WRTDATA edge | 2.17 us | >= 1.8 us | `_write_gate-fall_T3_1us.png` |
| Bit cell | 2.040-2.048 us | 2.0425 us +-0.1 % | edges from the saved CSV |
| WRTDATA rise | 4.4 ns | <= 50 ns | scope RISE |
| T4: last WRTDATA edge to gate high | 4.02 us | >= 2 us | `_write_gate-rise_T4_1us.png` |

| Format write, one track side (zone 0, 10,156 bytes) | 165.95 ms | 165.9 ms; one revolution is 152 ms, so the tail wraps over the preamble | `_format_t0s0_gate_20ms.png` |
| Format decode, track 0 side 0 | 12/12 sectors, all zero | | `_format_t0s0.flux` |
| Whole-disk format | 46.1 s | ROM-paced estimate 70-80 s | console log |
| Whole-disk write (`writedisk`) | 853-855 s, one block per 0.5-0.65 s | | `_writedisk_cadence_100ms.png` |

Fire latency was measured on RD, not taken from the firmware: the CH3 record
before the gate decodes to `... D5 AA 96 9D A7 96 DB DF DE AA`, and the gate
falls 3.1 us after the first flux edge following that `AA` (the earliest moment
the decoder can know it). The `backlog` field in the BLK line (7-32) is not the
backlog at the moment of fire; the scope settles it.

The board's format sounds just like a format on the Apple II: same
step-and-write rhythm, same layout and order.

## What broke

1. **Reads died after the probes went on.** RD sat flat at about 0.4 V, 0
   intervals per capture, on both heads, both disks; status, tach and stepping
   kept working. A cold reboot did not fix it. Cause: the M3 fault again, IR
   drop on +5V to CN104. Pin 11 read 4.6 V with the motor running (ERS minimum
   4.75 V). The +5V jumper was replaced with solid-core wire and the bench
   supply raised to 5.55 V: pin 11 then read 4.94 V running and 4.96 V idle.
   About 0.6 V is lost in the bench wiring even at idle; the rework is still
   owed (shorter, heavier +5V/GND runs to the tap).
2. **Format used up all 10 tries in 0.7 s without writing** (first `format 0 0`
   after `server on`). Cause: `mech_seek` to track 0 from an unknown position
   recalibrates, finds delta 0, and returned before READY; the format loop then
   saw READY high on every try. Fix `61d4690`: the seek waits READY after a
   recal too (new test `test_seek_after_recal_waits_ready`). Confirmed cold
   after reflashing: first try, then the whole disk with no retries.
3. **Flash failed** with `failed to exit flash XIP mode` (garbled QSPI ID
   `0x0316ef`), the same as the M4 note. A Pico power cycle fixed it.
4. Bench practice: I first said CN104 pins 15/17/19 were ground. They are
   +12 V (13/15/17/19); ground is 1/3/5/7. RD (16) and WRTDATA (18) sit between
   +12 V pins. Probes now go on with the mechanism supply off.

## Byte-for-byte check through the UniDisk

ADTPro imaged disk 2 on the IIe through the working UniDisk:
`TESTWRITE2.po` equals REF800K, 0 blocks differ, SHA-256 `bfed064f...657742ab`.
A disk formatted and written entirely by our board reads back exactly on the
original drive.
