# M7: the floppy behind SmartPort

Started 2026-10-12. Spec
`docs/superpowers/specs/2026-10-12-m7-floppy-behind-smartport-design.md`,
plan `docs/superpowers/plans/2026-10-12-m7-floppy-behind-smartport.md`,
branch `m7`. Built before the J2 mechanism breakout was wired, as if it were.

## Firmware ready for the bench (2026-10-12)

Not yet run on hardware.

What changed from M6:

- SmartPort calls go to a store: the M6 RAM disk or the floppy. The floppy
  store turns each call into a request to the M5 mechanism server on core 1
  and waits; ACK stays low meanwhile, so the card waits too (its reply wait
  has no timeout).
- The mechanism server runs from boot (U2/U4 enabled, /ENBL low, motor off).
  The disk is the floppy at boot; `sp disk ram` switches back to the M6 RAM
  disk, `sp disk floppy` back again.
- STATUS follows the disk: general byte `$F8`, `$E8` with no disk, `$FC`
  write-protected (ROM `Leda3`). READ/WRITE errors `$2F` no disk, `$2B`
  write-protected, `$2D` bad block, `$27` I/O. A read that needed a retry for
  bad data or a bad address, or found the head on the wrong cylinder, returns
  `$67` with the data (ROM `$E7`).
- CONTROL `$04` ejects (`$27` if the disk stays in). The eject button (GP22
  to GND) is ignored until `ejbtn on`: its wiring to GP22 is not settled
  (direct or through U5). When on, a 20 ms press ejects on release. The LED
  (GP26) is on while a request runs and while the motor turns.
- A Ctrl-Reset on the IIe during a long seek: the board lets go of the bus at
  once and drops the pending reply, so the card's single INIT try works.
- `imgcopy` writes the flash image to the floppy block by block (verified
  writes, about 13 min at M5 speed [estimate]). It makes a bootable test disk.
- The flash image now also holds `SPCOMPARE` (`tools/apple/SPCOMPARE.bas`,
  built by `tools/apple/mkimage.sh`).
- `splog` lines carry `ms=`, the time core 1 held the card off. `sp` shows
  `disk=`, `server=`, the maximum hold-off and the last mechanism reply.

Host tests: all C test programs pass, including `test_sp_floppy` (the M6
simulated Liron card against the floppy store and the M5 server on the fake
drive: boot reads, a seek to track 79 while the card waits, write, no disk,
write-protect, eject, a card reset during the seek). A code review against
both ROMs led to: sequence numbers on core-1 requests (no wedge after a slow
reply), the reset release above, the ROM's check order (no disk and
write-protect before the block range), `$27` on a failed eject, `$67`
following the ROM's `Z57` bits, and the eject button off by default.

### Bench steps (Rico)

Prerequisite (HANDOFF): J2 wired, ribbon rung out, isolation checks done
(+12 V against RD, WRTDATA and every signal), heavy +5 V run and the 4.7 uF
caps at the terminals, a clean read scan on drive A at 5.0 V, U2 channel
order checked. REF800K write-protected.

Power order: Pico (USB) first, then bench +5, then +12, then the IIe. At
shutdown everything off, the Pico too.

1. `make -C firmware flash`. Console `sp`: expect `disk=floppy server=on`.
   `oe off` is still the kill switch for the mechanism outputs.
2. REF800K in drive A, IIe on, `PR#5`. REF800K has no PRODOS file, so expect
   ProDOS's "UNABLE TO LOAD PRODOS" (or the card's own message). The `SPL`
   lines should show READBLOCK 0 (and more) with `ms=` values and `s=00`.
   That is the floppy path working end to end.
3. Make a bootable floppy: disk 2 in drive A (tab open; this overwrites disk 2,
   which only holds a REF800K copy), console `imgcopy`, wait for `IMGCOPY END
   00 1600 ...`. Then `PR#5`: ProDOS boots `/M6BOOT` from the floppy.
4. Scope the hold-off: CH1 /WRREQ (J1.10), CH2 ACK (J1.20), trigger CH1
   rising, 50 ms/div, during a `CAT` after a long seek (for example right
   after `PR#5`). ACK stays low for the whole core-1 time; compare with `ms=`.
5. Comparison program: `LOAD SPCOMPARE` (it is on disk 2 after step 3),
   `RUN`. Note the screen. Then with the working UniDisk on the Liron instead
   of our board (same disk 2), `RUN` again; they must match, except our
   STATUS `$05` bytes. Repeat with no disk and with the tab set.
6. Eject: CONTROL `$04` (any utility with an eject, or by hand). The button
   only after the GP22 wiring is settled, then `ejbtn on`.
7. Ctrl-Reset during a read that moves the head (for example `CAT` right after
   swapping to a far track): the IIe recovers and `PR#5` still works.
8. Write: in BASIC on disk 2, `SAVE HELLO`, `CATALOG`, power everything off
   and on, `CATALOG` again: the file survives (it is on the floppy now).

Watch item: core 1 now runs its idle loop from flash all the time. Compare
`ack_us` with the M6 value (5.3 us); if it grew, look at flash contention.

If step 2 shows `s=27` on every read: `sp` (mech `st=`, `soft=`), then a
`readdisk` with `server off` as in M4 to separate the mechanism from the
SmartPort side.
